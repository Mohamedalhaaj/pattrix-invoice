# استرجاع النسخة الاحتياطية من GitHub

**التاريخ:** 2026-08-01
**الحالة:** معتمد، بانتظار التنفيذ

## المشكلة

التطبيق يرفع النسخ إلى `pattrix-invoice-backups` ولا يقرأ منها. الدوال الموجودة `ghTest`
و`ghPush` فقط — لا مسار جلب إطلاقًا.

الأثر العملي: `localStorage` منفصل لكل متصفح على كل جهاز، فمن يفتح الرابط على الهاتف يجد
تطبيقًا فارغًا. الطريقة الوحيدة لنقل البيانات اليوم هي تصدير ملف JSON من الحاسوب ونقله
يدويًا واستيراده. المستودع الخاص فيه البيانات المطلوبة أصلًا، لكن التطبيق لا يستطيع
الوصول إليها.

## الحل

زر **«استرجاع من GitHub»** في الإعدادات ← نسخ احتياطي على GitHub. يجلب أحدث نسخة من
المستودع ويستبدل بها محتوى الجهاز، بعد تأكيد يعرض الفرق بين الطرفين.

## القرارات

| القرار | المُعتمد | السبب |
|---|---|---|
| أي نسخة | الأحدث تلقائيًا | ٩٥٪ من الحالات: تفتح الهاتف وتريد آخر ما لديك. القائمة تضيف شاشة بلا مقابل |
| نطاق الاستبدال | كل شيء عدا `settings.gh` | يمنع أن تزرع نسخة قديمة توكنًا منتهيًا فتكسر المزامنة |
| الحماية | تأكيد يعرض الفرق | ترى ماذا تربح وماذا تخسر قبل أن تقرر. العملية لا تُتراجع |
| تحديد الأحدث | سرد المجلد وترتيب الأسماء | أسماء ISO ترتيبها الأبجدي هو الزمني. يعمل مع النسخ الموجودة بلا ترحيل |

### بدائل مرفوضة

- **بناء الاسم من `lastPush` المحلي** — الجهاز الجديد ليس فيه `lastPush`، وهو الحالة
  التي بُني الزر لأجلها.
- **ملف `latest.json` يكتبه الرفع** — يغيّر سلوك الرفع ويكتب مرتين، والنسخ المرفوعة
  قبل التغيير ليس لها `latest.json`.

## البنية

ثلاث دوال، كل واحدة غرض واحد، على نسق `ghTest`/`ghPush` القائم.

### `ghLatestBackup(g)`

```
GET /repos/{repo}/contents/{folder}?ref={branch}
```

ترشّح `type === 'file'` والاسم يطابق `/^pattrix-backup-.*\.json$/`، ترتّب تنازليًا
بـ `localeCompare`، تعيد الأول.

- المجلد فارغ أو غير موجود (`404`) ← خطأ «لا توجد نسخ بعد». حالة حقيقية على مستودع
  جديد، لا عطل.
- لا ملف يطابق النمط ← نفس الرسالة.

### `ghPull(g)`

تجلب الملف الذي أعادته `ghLatestBackup` بترويسة:

```
Accept: application/vnd.github.raw
```

بدل قراءة `content` بصيغة base64. سببان: يتجاوز حد المليون بايت الذي ستبلغه النسخ مع
الوقت، ويُسقط فك ترميز base64 للعربية وهو موضع أخطاء متكرر.

تتحقق قبل الإعادة أن الناتج كائن وأن `invoices` و`clients` مصفوفتان. ملف تالف يرمي خطأ
ولا يصل إلى مرحلة الاستبدال.

تعيد `{ data, name }` — الاسم مطلوب لعرض تاريخ النسخة في التأكيد.

### `ghRestore()`

1. `ghPull` ← جلب
2. مقارنة الأعداد: الوارد مقابل `DB` الحالي
3. `confirm` يعرض الطرفين — إلغاء يعني توقف تام قبل أي كتابة
4. الدمج:

```js
DB = { ...incoming, settings: { ...incoming.settings, gh: DB.settings.gh } };
```

5. `saveDB()` ثم `renderApp()`

`settings.gh` المحلي يُحفظ كما هو: التوكن واسم المستودع والفرع والمجلد وإعداد الرفع
التلقائي — كلها تخصّ هذا الجهاز وهذه الجلسة، لا النسخة.

## الأخطاء

بنفس نمط `ghPush`: `try/catch` حول كل `fetch` مع `ghNetErr`، وفحص `res.ok` مع قراءة
`json.message` من ردّ GitHub.

| الحالة | السلوك |
|---|---|
| لا مستودع أو لا توكن | `L('ghNeedCfg')` — نفس رسالة `ghPush` |
| `404` على المجلد | «لا توجد نسخ بعد» |
| `401` / `403` | رسالة GitHub الحرفية |
| شبكة | `L('ghBlocked')` عبر `ghNetErr` |
| JSON تالف أو بنية غير متوقعة | «ملف النسخة تالف» — قبل أي استبدال |

## الواجهة

زر ثالث بجانب «اختبار الاتصال» و«رفع نسخة الآن»، بنمط `.btn` العادي لا `.primary`:
الرفع فعل يومي، والاسترجاع فعل نادر لا ينبغي أن يجاوره في البروز فيُضغط بالخطأ.

نصّ الحالة تحت الأزرار يُعاد استخدامه لعرض النتيجة، كما تفعل `ghTest`.

## الصلاحيات

الاسترجاع قراءة فقط. التوكن الحالي `Contents: Read and write` يكفي — لا تغيير ولا توكن
جديد.

## خارج النطاق

- اختيار نسخة أقدم من قائمة
- الدمج الذكي بدل الاستبدال (تعارضات الفواتير تحتاج تصميمًا منفصلًا)
- المزامنة التلقائية عند الفتح — الاسترجاع يبقى بضغطة صريحة
